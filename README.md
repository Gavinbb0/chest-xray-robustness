# Chest X-ray Robustness

Code accompanying the project report *Robustness of Deep Learning Models to Image
Degradation in Chest X-ray Pneumonia Classification* by Li Yuanbai. This repository
contains a consolidated implementation of the experiment described in the report.

Two-stage pneumonia classification experiment using ResNet18:

1. **Baseline:** fine-tune ImageNet-pretrained ResNet18 on clean chest X-rays.
2. **Robust:** fine-tune the same architecture with randomly selected clean, blur, Gaussian noise, reduced contrast, or reduced brightness inputs.

Both models are calibrated separately on the **validation** split, then compared on the untouched **test** split under clean images and five degradations. This repository is research/education code, not a clinical diagnostic device.

## Reported findings

The following AUROC values are from the project report. They are **reported results**,
not values generated by running this repository anew. Gaussian noise values are the
mean and standard deviation over three noise realizations, rather than independent
training runs.

| Test condition | Standard ResNet18 | Degradation-aware ResNet18 |
| --- | ---: | ---: |
| Clean | 0.9219 | 0.9595 |
| Gaussian blur, level 4 | 0.7382 | 0.9480 |
| Gaussian noise, level 4 | 0.6773 ± 0.0133 | 0.9559 ± 0.0023 |
| Contrast reduction, level 4 | 0.8744 | 0.9544 |
| Brightness reduction, level 4 | 0.8676 | 0.9522 |
| JPEG compression, level 4 | 0.8381 | 0.9468 |

The experiment used the Chest X-Ray Images (Pneumonia) dataset associated with
Kermany et al. (2018). Its official 624-image test split was held out; the original
training split was divided into 80% training and 20% validation within each class.
The study used one dataset and one training run per model. Patient-level separation
was not explicitly checked. All five test degradations were synthetic; only JPEG
compression was absent from robust training. These results do not establish clinical
reliability or generalization to other hospitals.

## Setup

Python 3.10+ and compatible PyTorch / torchvision installations are required.

```bash
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
pip install -e .
```

The pretrained ResNet18 weights download on first training run. If offline, pass `--no-pretrained`; this changes the experiment to training from random initial weights. Choose the appropriate PyTorch installation for your CUDA environment if using an NVIDIA GPU.

## Data

The original dataset is **not included**. Expected labels are exactly `NORMAL` and `PNEUMONIA`; ImageFolder maps them to 0 and 1 respectively. Source folder:

```text
path/to/chest_xray/
  train/
    NORMAL/*.jpeg
    PNEUMONIA/*.jpeg
  test/
    NORMAL/*.jpeg
    PNEUMONIA/*.jpeg
```

Prepare a reproducible 80/20 split **within each training class**, copying the source test images without using them to select a model or threshold:

```bash
cxr-robust prepare --source path/to/chest_xray --data-dir data/chest_xray_split
```

If you already have `train/NORMAL`, `train/PNEUMONIA`, `val/NORMAL`, `val/PNEUMONIA`, `test/NORMAL`, and `test/PNEUMONIA`, point `--data-dir` directly at that existing root. The prepare command requires an empty destination, so accidental re-runs cannot mix splits.

## Run the full experiment

```bash
cxr-robust train --variant baseline --data-dir data/chest_xray_split --checkpoint outputs/baseline.pth
cxr-robust train --variant robust   --data-dir data/chest_xray_split --checkpoint outputs/robust.pth

cxr-robust calibrate --data-dir data/chest_xray_split --checkpoint outputs/baseline.pth
cxr-robust calibrate --data-dir data/chest_xray_split --checkpoint outputs/robust.pth

cxr-robust compare --data-dir data/chest_xray_split --baseline outputs/baseline.pth --robust outputs/robust.pth --output outputs/results
cxr-robust plot --metrics outputs/results/metrics.csv --output outputs/results/robustness.png
```

By default training uses 10 epochs, batch size 32, Adam learning rate 1e-4, seed 42, and the checkpoint with the lowest clean validation loss. Use `--epochs`, `--batch-size`, `--lr`, `--seed`, and `--device cpu|cuda|auto` to adjust. Robust training selects one of five variants with equal probability for each image; it does **not** add JPEG to training, preserving the original Stage 2 design.

The `calibrate` command computes a Youden-J threshold from validation predictions and stores it next to each checkpoint as `.json`. AUROC uses continuous pneumonia probabilities; accuracy, sensitivity, specificity, F1 and confusion matrix use that model's saved threshold. You can also supply a pre-existing pure `state_dict` checkpoint (such as the original `baseline_resnet18.pth` or `robust_resnet18.pth`); calibrate it on the same validation split, or pass `--baseline-threshold 0.8009 --robust-threshold 0.5728` to `compare` if you specifically need the thresholds reported in the original experiment.

The `compare` output contains:

- `metrics.csv`: model × condition × severity level, including threshold metrics and AUROC.
- `comparison.csv`: AUROC of both models and their difference at every level.
- `noise_repeats.csv`: separate runs using noise seeds 42, 123, 999 for severity levels 1–4; both models see identical sampled noise for each seed.
- `robustness.png` after `plot`: measured AUROC curves, with no hard-coded results.

Severity level 0 is clean. Levels 1–4 use:

| Degradation | Values at levels 1, 2, 3, 4 |
| --- | --- |
| Gaussian blur radius | 0.5, 1.0, 2.0, 4.0 |
| Gaussian noise standard deviation | 0.02, 0.05, 0.10, 0.15 |
| Contrast factor | 0.8, 0.6, 0.4, 0.2 |
| Brightness factor | 0.85, 0.70, 0.50, 0.30 |
| JPEG quality | 80, 50, 25, 10 |

Noise is applied equally across the three RGB channels after resizing and before ImageNet normalization, matching the original evaluation convention. Pillow transformations are applied before converting the image to a tensor. The first seed (42) is used in the main comparison CSV; the other two are available separately for variability analysis.

## Single model and explanation figure

```bash
cxr-robust evaluate --data-dir data/chest_xray_split --checkpoint outputs/baseline.pth --name baseline --output outputs/baseline_eval
cxr-robust gradcam --image path/to/example.jpeg --baseline outputs/baseline.pth --robust outputs/robust.pth --output outputs/results/gradcam.png
```

Grad-CAM targets the pneumonia logit in the last ResNet18 convolution block. The figure overlays heat maps on the same resized source image; it is a qualitative diagnostic, not an anatomical validation.

## LecTrace presentation

The [LecTrace script](presentation/lectrace_presentation.py) and [10-minute speaking script](presentation/lectrace_speaking_script.md) walk through five selected evaluation states: the image and label, severe noise, the standard model's decision, the degradation-aware model's decision, and full-test AUROC. This is an explanation of saved results, **not** a live ResNet18 inference or a training run.

LecTrace requires Python 3.11 or newer. In a compatible environment, run:

```bash
pip install lectrace
lectrace serve presentation/lectrace_presentation.py --port 7001
```

Open the local URL printed by LecTrace. The script uses the checked-in aggregate [summary CSV](presentation/results/metrics/final_summary.csv). It also accepts three optional figures at `presentation/results/figures/error_cases.png`, `noise_preview_v2.png`, and `severe_standard_vs_robust.png`. The presentation remains runnable without them and shows explanatory text in their place. Figure files are excluded from this repository because the code presentation does not require uploading source X-ray imagery.

## Repository scope and reproducibility

This is a cleaned implementation of the supplied `stage_1` and `stage_2` scripts. One-off GPU/image checks, manual case selections, pasted result tables, and duplicated per-degradation evaluation files are intentionally consolidated into the commands above. Generated images, checkpoints, and the dataset are excluded by `.gitignore`. Re-running training may yield different numbers from the report due to split membership, package/hardware versions, and training randomness; evaluating the original checkpoints with the original split is the closest comparison.
